### Deviations from the roadmap (honest count)
* **Renamed:** the roadmap's `chi2_*`, `expon_*`, `binomial_*` exist as `chisq_*`, `exp_*`, `binom_*`; the roadmap names are registered as aliases. Aliases are **not** counted as functions.
* **Replaced:** `ci_z_mean`, `ci_t_mean`, `ci_proportion` return one interval string `[low, high]`; the separate `z_ci_low/high`, `t_ci_low/high`, `prop_ci_low/high` functions were added too.
* **Gap-fill added:** `mode`, `quantile`, `corr`, `cv`, `expon_inv` and others (27 functions in total).
* **Counting rule:** a function counts only if it has a checked `example` AND an independent cross-check AND a bad-input test. All 827 now meet that.

### Unit conventions
* Reverse conversions use the exact defined factor (e.g. `ft2m(1)` = `0.3048`, `mi2km(1)` = `1.609344`, `nmi2km(1)` = `1.852`), and each pair has a round-trip test.
* `kb2mb`, `mb2gb` use decimal (1000) steps. `mpg2l100km(0)` and `l100km2mpg(0)` are Math ERROR.

### Test layers
`_extended_checks` compares against `statistics`, `math`, `cmath`, brute force, numerical integration of densities, identities and round trips. `_bad_input_checks` covers a table of domain errors, a too-few / too-many-arguments sweep over every function, and a sweep (0, -1, 0.5, 1e308) that fails if a Python exception ever escapes. `ARG_LIMITS` stops huge inputs hanging loop-heavy functions.

## 2. Comprehensive Function Library Overview

The function registry spans a broad array of disciplines, ensuring rigorous support for engineering calculations, advanced calculus, complex numbers, statistics, and number theory.

### A. Physics, Mechanics, Acoustics & Optics
* **`kinetic_energy(mass, velocity)`**: Computes translational kinetic energy: $KE = \frac{1}{2}mv^2$.
* **`spring_pe(k, displacement)`**: Computes elastic potential energy stored in a spring: $PE = \frac{1}{2}kx^2$.
* **`projectile_range(velocity, angle_deg)`**: Computes ideal horizontal projectile range over flat ground using standard gravity ($g = 9.80665\text{ m/s}^2$): $R = \frac{v^2 \sin(2\theta)}{g}$.
* **`z_redshift(observed, emitted)`**: Calculates cosmological/Doppler redshift: $z = \frac{\lambda_{\text{obs}} - \lambda_{\text{emit}}}{\lambda_{\text{emit}}}$.
* **`synodic_period(p1, p2)`**: Calculates synodic period of two orbiting bodies: $S = \left\vert{}\frac{1}{\frac{1}{P_1} - \frac{1}{P_2}}\right\vert{}$.
* **`snells_law`, `critical_angle`, `photon_energy`, `sound_intensity_level`, `lensmaker`**: Optics and acoustics calculation utilities.

### B. Advanced Mathematics, Calculus, Number Theory & Special Functions
* **`mobius(n)`**: Classical Möbius function $\mu(n)$ (`exact=True`). Returns `1`, `-1`, or `0`.
* **`next_prime(n)`**: Smallest prime number strictly greater than integer $n$.
* **`erf(x)`**: Gauss error function: $\text{erf}(x) = \frac{2}{\sqrt{\pi}} \int_0^x e^{-t^2}\,dt$.
* **`soft_plus(x)`**: Smooth approximation to ReLU activation: $f(x) = \ln(1 + e^x)$.
* **`deriv` / `integrate` / Numerical solvers**: Root finding, ODE solvers (Euler, RK4), and numerical quadrature methods (Trapezoidal, Simpson's, Gauss-Legendre).

### C. Complex Numbers & Linear Algebra
* **`c_div(a, b, c, d)`**: Complex division $\frac{a + bi}{c + di}$ returned as a complex value (see section M).
* **`vector_proj3(ux, uy, uz, vx, vy, vz)`**: Scale factor k (projection = k·v) of 3D vector $\vec{u}$ onto $\vec{v}$: $\frac{\vec{u} \cdot \vec{v}}{\Vert{}\vec{v}\Vert{}^2}$.
* **Matrix operations**: Determinants, inverses, eigenvalues, rank, trace, and cross products.

### D. Statistics, Probability & Financial Modeling
* **`skewness(x1, x2, ...)`**: Adjusted Fisher-Pearson sample skewness coefficient. Requires $\ge 3$ values.
* **`npv(rate_pct, cf0, cf1, ...)`**: Net Present Value of a cashflow series starting at $t=0$.
* **Probability distributions**: PDF, CDF, and inverse functions for Normal, Binomial, Poisson, Student's t, Chi-Square, F-distribution, Gamma, and Beta distributions.

### K. Sprint 8 — List and matrix types (43 new functions)
* **Syntax:** a list is `{1, 2, 3}`; a matrix is a list of equal-length lists `{{1, 2}, {3, 4}}`. `{ }` is now the list literal (it used to be a second kind of parenthesis); `( )` and `[ ]` remain ordinary grouping. A missing final `}` is allowed, like a missing `)`. Lists can be stored (`{1,2,3} -> A`), used through `Ans`, and display element by element in the current Norm/Fix/Sci mode. Limit: 10,000 elements.
* **Arithmetic:** `+ - * / ^ mod` and the postfix `! % ² ³` work element by element between a list/matrix and a number, or between two of the same size (different sizes give Math ERROR). Matrix algebra: `matrix * matrix` is the matrix product, `matrix * list` a column-vector product, `list * matrix` a row-vector product, `M^n` (whole n up to 1000, negative = inverse), `M²`, `M³`, `M⁻¹`. Division by a matrix, non-square powers and singular inverses give Math ERROR. Integer and fraction entries stay exact.
* **Existing functions accept lists:** a function that takes "many numbers" (maximum 50 or unlimited arguments: `mean`, `stdev`, `median`, `max`, `gcd`, `irr`, `payback`, `npv`, `linreg_slope`, ...) splices a list's elements in as its arguments, so `irr({-1000,300,400,500})` equals `irr(-1000,300,400,500)`; two lists are joined (`linreg_slope({1,2,3},{2,4,6})`). Other functions work element by element (`sin({0,30,90})`, `atan2({1,0},{0,1})`, a number is repeated against a list), and if the argument count does not fit, the elements are spliced (`det3({{1,2,3},{4,5,6},{7,8,10}})`). The result keeps the list/matrix shape.
* **Lists (23, category Lists, 1-based positions):** `list_len list_get list_slice list_sort list_rev list_sum list_prod list_cumsum list_cumprod list_diff list_seq list_range list_linspace list_concat list_append list_fill list_dot list_map list_argmax list_argmin list_index list_count list_unique`. `list_map('x^2+1', L)` evaluates an expression in `x` for every element (angle mode and variables inherited). `list_range` and `list_linspace` give exact decimals (`list_range(0,0.3,0.1)`).
* **Matrices (20, category Matrices):** `mat_new mat_eye mat_zeros mat_diag mat_rows mat_cols mat_get mat_row mat_col mat_t mat_flatten mat_trace mat_det mat_inv mat_rank mat_mul mat_pow mat_solve mat_rref mat_norm_f`. Determinant, inverse, solve and rref are exact for integer/fraction input (size up to 30 x 30); float input gives floats. The older fixed-size functions (`mat_inv3`, `det4`, ...) are unchanged and still return text.
* **Implementation notes:** values are `Lst` / `Mat` (tuple subclasses) handled in the tree walker (`list` node, element-wise `_ew`, `_box_binary`) and in `Calculator._apply_boxed`; the registry has a new `lists=True` flag for functions that receive lists untouched (all 43 new functions).
* **Verification:** element-wise arithmetic against plain Python, matrix products against triple loops, determinants against permutation expansion (sizes 1-5), `M * M⁻¹ = I`, `mat_solve` by substituting back, matrix powers against repeated products (including Fibonacci and negative powers), list functions against Python builtins, and lists passed to `irr`, `payback`, `npv`, `mean`, `stdev`, `median`, `gcd`, `linreg_slope`, `det3`, `sin`, `atan2` against their scalar forms; plus about 130 bad-input cases (size mismatches, singular matrices, bad positions, wrong types).

### M. Complex numbers as a value type (+5 functions)
* **Syntax and display:** `i` is the imaginary unit (`3+4i`, `2i`, `(1+2i)*(3-i)`, `i^2 = -1`); only lowercase `i` (the capital I is not a name). Results show as `a+bi` (`i` and `-i` without the coefficient 1, a pure imaginary as `2i`), each part in the current Norm/Fix/Sci mode. **A result with imaginary part 0 is an ordinary real number**: `(1+i)*(1-i)` is `2`, `exp(i*pi)` is `-1` (parts below 1e-14 of the larger part are treated as 0). Python type `Cx`.
* **Arithmetic:** `+ - * / ^ ² ³ ⁻¹ %` and negation work on complex values (integer powers use exact repeated multiplication, others the principal value). `! mod`, comparisons, `max`, `floor`, `round` and every function without a complex version give Argument ERROR. Lists and matrices may hold complex numbers (changed in section O); `list_sort`, `mat_det`, `mat_inv` and the other exact-arithmetic matrix functions need real numbers.
* **Functions of complex values:** `sqrt cbrt exp ln log log2 sin cos tan sinh cosh tanh asin acos atan asinh acosh atanh sq cube inv pow abs` accept complex arguments (**trigonometric ones use radians for complex arguments**). New: `re(z)`, `im(z)`, `conj(z)`, `arg(z)` (in the current angle mode), `rect(r, angle)`; they also accept real numbers.
* **The `c_*` functions** (still `(real, imaginary)` pairs, still in degrees for polar forms) now return complex values; a complex value may stand for a pair: `c_mul(1+2i, 3+4i)`, `c_conj(3+4i)`, `c_pow_n(1+i, 4)`. Limitation: a value with imaginary part 0 is a plain real number, so `c_mag((1+i)*(1-i))` is an Argument ERROR (write `c_mag(2, 0)`).
* **Complex mode:** `complex on` / `complex off` (command line; `Calculator.complex_mode`) widens real functions: `sqrt(-4) = 2i`, `ln(-1) = πi`, `log(-100)`, `log2`, `acosh(0.5)`, `atanh(2)` and `(-8)^(1/3) = 1+1.732i` (in real mode the real cube root -2 is kept). `complex polar` shows results as `r∠θ` in the current angle mode (`complex rect` returns to `a+bi`).
* **Verification:** arithmetic on 40 random pairs against Python's `complex`; every function in the table against `cmath` at six points (plus identities `sqrt(z)² = z`, `exp(ln z) = z`, `sin²+cos² = 1`, `z·conj z = |z|²`); angle-mode behaviour of `arg`/`rect`; complex mode, polar display and about 30 error cases.

### N. Old text matrix functions now return real matrices and lists

### O. Equation and table modes (7 functions, category "Equations & Tables")
* **Complex numbers in lists and matrices:** `{1+i, 2, -3i}` is a valid list; element-wise arithmetic, broadcasting (`abs({3+4i,5})`) and the matrix product work with complex entries. Sorting and the exact-arithmetic functions (`mat_det`, `mat_inv`, `mat_rank`, `mat_rref`, `list_sort`, `list_argmax`, ...) refuse them (Argument ERROR).
* **`simul(M)`:** simultaneous linear equations from the augmented matrix `{{a1,b1,c1},{a2,b2,c2}}` (n equations, n unknowns, 2 to 30); exact for integer/fraction input; Math ERROR when there is no unique solution (singular, inconsistent or dependent).
* **`poly_roots(L)`:** all roots of a real polynomial (coefficients highest power first, degree 1 to 10) as a list, real roots ascending then complex ones by real part then imaginary part (`x^4-1` gives `{-1, 1, -i, i}`). Degree 1 and 2 use closed forms; higher degrees use Durand-Kerner iteration polished by Newton. **Repeated roots are exact** for rational (decimal) coefficients: an exact square-free factorisation (Yun's algorithm over fractions) finds each distinct root once and repeats it by its multiplicity, so `(x-1)^5` gives five exact 1s instead of a ring of 1e-3 errors. `poly_from_roots(L)` is the inverse (monic polynomial, real or complex roots).
* **`poly_ineq(L, op)`:** the solution set of `p(x) > 0`, `>=`, `<`, `<=` (operators in quotes; `≥`/`≤` accepted) as text intervals: `(-inf, 1) U (2, inf)`, `[1, 2]`, `{1}` for an isolated point, `all real numbers`, `no solution`. Closed ends only for non-strict operators; even-multiplicity roots are handled correctly.
* **`nsolve2(f, g, x0, y0)`:** two nonlinear equations in `x`, `y` (expression strings) by Newton's method with a numerical Jacobian and backtracking; returns `{x, y}`; Math ERROR when it does not converge or the Jacobian is singular. It finds the solution nearest the start; try other starting points for other solutions.
* **Table mode:** `table1(f, start, end, step)` returns a matrix of rows `{x, f(x)}` and `table2(f, g, start, end, step)` rows `{x, f(x), g(x)}` (up to 500 rows; the step must lead from start to end; the angle mode applies). x values are exact (0.25 steps are exact decimals). The command line has `table f(x), start, end, step` and `table f(x), g(x), start, end, step`, which print an aligned table; the matrices feed list and statistics functions (`linreg_slope(mat_col(T,1), mat_col(T,2))`).
* **Verification:** `simul` against systems built from known solutions (2 to 6 unknowns); `poly_roots` against roots constructed with `poly_from_roots` (itself checked against elementary symmetric polynomials), residuals `|p(root)|`, Vieta's sum and product for random polynomials up to degree 8, and 12 fixed cases including triple, quadruple and quintuple roots; `poly_ineq` by sampling 60 random points per polynomial and operator and checking every root point; `nsolve2` against known solutions and bisection; tables against direct evaluation. A bug found on the way: the exact polynomial division dropped trailing zero coefficients of the quotient, which made the square-free factorisation lose roots (`x^3-1` returned one root); fixed and covered by the tests.

### U. Symbolic-looking output (`sym on|off`, +1 function `sym_form`)
